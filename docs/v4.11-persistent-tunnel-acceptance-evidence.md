# v4.11 Persistent Tunnel Acceptance Evidence

Date: 2026-08-25
Branch: `dev`
Scope: local pre-release acceptance for v4.11.0 before the user installs the candidate installer.

## Claim boundary

v4.11 keeps one saved OpenAI tunnel identity and continuously reconciles a native managed runtime back to the current Desktop MCP loopback endpoint. It retries transient failures indefinitely with capped backoff until the user disables/stops the tunnel.

This build **does not claim strict zero downtime**. The installed official `tunnel-client` exposes managed runtime supervision and health/readiness/control-plane-poll checks, but its CLI does not expose a documented/testable ready-before-retire overlap or A/B handoff primitive. `readyBeforeRetire` and `strictZeroDowntime` therefore remain false and the UI/Doctor reports that capability boundary instead of inferring it from reconnect behavior.
